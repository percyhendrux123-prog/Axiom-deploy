AXL

A five-line card our agents use to say where a job stands, and a checker that turns it red when the proof isn't there.

P. K. Stewart · Deploy Axiom · Published Nov 25, 2026

An agent's status note reads the same whether it is true or not. "Done, tests pass, it's live" looks exactly like a note where none of that happened.

AXL is how we make a status note checkable. It is a five-line card with a fixed set of words, and a short script that reads the card and checks every piece of proof it names. No model is involved in the check.

The card

AXL/1  A296 · REVIEW · NEED owner:approve
ASK    Review the local fixture, not production.
EV     file:fixtures/proof.txt
RISK   low · REVERSIBLE yes · TOUCHES none
NOTE   No live data was used.

That is an example card, not a live job. The checker reads it back in plain English:

Card A296 is in review.
Needs owner to approve.
Ask: "Review the local fixture, not production."
Evidence (file): "fixtures/proof.txt"
Risk is low; reversible: yes; touches: none.
Note: "No live data was used."

Line by line

  • AXL/1: the job's code, where it stands, and who it needs for what. State is one of READY, RUNNING, BLOCKED, REVIEW, DONE or PARKED. Who is the owner, the front-door agent, a named agent, or none. For what is decide, approve, input, look, or none.
  • ASK: the one thing being asked, in plain English, on one line.
  • EV: the proof, at least one piece. A commit, a file, a screenshot, a saved test log, a link, or a job card.
  • RISK: how bad it is if this is wrong (low, med or high), whether it can be undone, and whether it touches a client, money, something public, or data.
  • NOTE: optional context, on one line.

Anything outside those words is an error, and the error names the word.

What the checker returns

  • GREEN. Every word is valid, and every piece of proof exists: the file is on disk, the commit is in the repository, the card is on the board, the link answers.
  • RED. A word is wrong, the card's meaning changed after it was written, or the proof it names isn't there. A red note is fixed, never posted as done.
  • LEGACY. Plain prose. Shown as written, checked for nothing.

GREEN means the proof exists. It does not mean the work is good, and it never means the work is approved.

The checker only reads. It opens the job board read-only, fetches a link only when it is told it may, and never runs anything written in a card. A test log counts as proof that a test run was saved, not as proof that it passed.

How the owner answers

ReplyMeans
A296 goYes, proceed.
A296 noDon't.
A296 holdPause it.
A296 whyExplain it.
A296 showShow me the proof.
A296 change: use the shorter exampleDo it this way instead.

Case doesn't matter, so a reply typed fast on a phone still reads. A bare "go" works only when exactly one open card is waiting on the owner. Anything else comes back unparsed, and the agent asks instead of guessing.

A parsed reply changes nothing by itself. The front-door agent still checks it against the limits of authority before anything moves.

Why fixed words

A template can be filled with anything. A fixed vocabulary can be refused. Because every card turns into fixed English and back again without loss, a card whose meaning was edited after the fact no longer matches its saved English, and it turns red.

The same short words work for both sides. Agents write them without a learning curve, and the owner can read a card in the time it takes to glance at a phone.

Where it stands

We built AXL on November 8, 2026. Its 45 tests passed again on November 25.

The rule is written: our agents' status notes, review notes and handoff lists are meant to be AXL cards. The habit has slipped. Most handoffs this month went back to plain prose, which is the exact gap AXL exists to close.

The checker is not public yet.
