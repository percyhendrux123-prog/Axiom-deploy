# Homepage ledger: counting rule

The ledger on the homepage (`#proof`) shows three numbers from our own operating ledger, `00-COMMAND/OS-EVENTS.csv` on the operations Mac. It holds our company's records, not client data. The CSV is read, never written, by this repo.

## The rule

One CSV data row is one outcome. Count only rows whose `date` starts with an ISO date (`YYYY-MM-DD`), up to and including the "as of" date.

| Number | Counts | Page label |
|---|---|---|
| Outcomes | every dated row | outcomes on record |
| Verified | rows with `status` exactly `verified` and a non-empty `evidence` field | verified against recorded evidence |
| Recovered | rows with `failure_recovered` exactly `yes` | with a failure caught and recovered |

Rows marked `done`, `completed`, `user_reported`, `verified_partial` or blank are outcomes but are not counted as verified. Free-text values in `failure_recovered` (for example `true` or `yes: <note>`) are not counted as recovered. The rule undercounts rather than guesses.

"Verified" means the row records a readback against something real (a file, page, message record or test run) in its `evidence` field. It does not mean a third party audited it, so the page does not say "independently".

"Recovered" counts outcomes in which at least one failure was caught and recovered. It is not a count of individual failures.

## Refresh

```
node scripts/ledger-count.mjs <path>/00-COMMAND/OS-EVENTS.csv --through YYYY-MM-DD
```

Put the three printed numbers into `index.html` (`#proof .ledger__num`), set the "as of" date in the ledger head to the `--through` date, and update the literal numbers in `tests/motion.test.mjs`, `tests/remake.test.mjs`, `tests/browser/motion.test.mjs` and the homepage hash in `tests/fixtures/polish-content.json`. Only numbers printed by the script go on the page.
